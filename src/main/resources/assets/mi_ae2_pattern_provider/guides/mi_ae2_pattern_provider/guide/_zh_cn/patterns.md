# 样板与自动合成

供应仓就是货真价实的 AE2 样板供应器，所以供应器的常识都适用 —— 只有几条是处理阵列特有的。

## 用处理样板

阵列是**机器**，不是合成格，所以它认的是**处理样板**：

* **输入** = 配方消耗的材料。
* **输出** = 配方产出的东西。

*工作台样板*（3×3 摆法那种）在这里跑不了，因为阵列里没有任何东西能「把材料摆进格子」。

## 合成循环

1. ME 系统发现缺料，从供应仓里挑一条样板。
2. AE2 把这条样板的**输入**推进供应仓的输入槽 —— 物品与流体一次到位。
3. 阵列取走材料，按输入料量与输出格空间跑尽可能多的批数，把成品写进供应仓的输出槽。
4. 供应仓把成品导出到网络，并释放这条样板。

供应仓会一直占着这条样板，直到**它自己的**产物回到网络（`LOCK_UNTIL_RESULT`）。这块缓冲正是这样才安全：
产物还在路上时，同一份输入绝不会被重复推进来。

## 多仓单活：为什么允许放多个，但同一时刻只有一个在工作

阵列会把产物写进**聚合库存里任意一个可接纳的输出格**，并不保证落回「发料的那一仓」。而每个供应仓的产物锁定、
余料回收、等待自己产物解锁都是**按仓独立**的 —— 产物落到别的仓时，那一仓会解锁它自己的逻辑，
发料仓却永远等不到自己的产物，于是卡死。

**解法**：让非活动仓把输出空间**报成 0**（锁成空）。这样产物无处可去，只能进正在工作的那个仓，归属重新确定。
于是「多仓」是安全的，只要保证**同一时刻只有一个仓在接单**：

1. 活动仓接单、锁输出、收产物；
2. 其它仓输出全锁空、`pushPattern` 直接拒绝（AE 会自动重试）；
3. 活动仓交完自己的产物（产物不再被请求 + 输入空 + 输出空，连续约 2 秒）就释放，下一个仓接单。

这条「是否该让位」的判定完全从**实际状态**推导，不写进存档，所以读档、订单取消、拆网络都不会留下脏状态。

> 还有一个边界：**别在同一个阵列里同时用原生输出仓**（MI 的物品/流体输出仓）。产物可能被它接走，
> 那份产物不归任何供应仓，等待产物返回的仓会一直等。

## 「一直等待」不一定是 bug

当供应仓拒收一次推进时（例如它的输出空间与容量查询口径不一致），ME 终端显示的是**一直等待**而不是失败。
AE2 每 tick 重试，而供应仓会在同一次调用里把条件消掉（也顺手把自己遗留的无上限标志夹回普通容量），
所以下一次尝试通常就能过。

实际后果：

* 大合成可能被拆成多次小批量。这是有意的：避免槽满时产物被销毁。
* 如果阵列已经**完全没有**空间放产物，合成就会等待。让网络把产物抽走，或者给网络留出空间即可。
* 拆批**不会**增加总耗电：EU 与耗时按上游语义随批数缩放。
